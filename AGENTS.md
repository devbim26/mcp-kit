# AGENTS.md — как работать с этим репозиторием

Вы — агент, которому поручили сделать MCP-сервер и плагин DeepSeek
Harness на основе существующего проекта или HTTP-сервера.

## Главное правило

Работайте по скиллу **`mcp-harness`**:

- локально: `~/.agents/skills/mcp-harness/SKILL.md`
- в репозитории: <https://github.com/devbim26/skills/tree/main/mcp-harness>

Вызовите скилл (`skill` с именем `mcp-harness`) или прочитайте SKILL.md
перед тем, как писать код. Этот репозиторий — **каркас**, а не инструкция:
здесь `McpApp`, шаблоны сервера, тесты. Порядок работы, плагин DSH,
Discover, персональные ссылки, типовые сбои — в скилле.

## Что здесь лежит

| Путь | Зачем |
|---|---|
| `mcp_kit/app.py` | `McpApp` — FastMCP + FastAPI + Bearer + `/health` + аудит |
| `mcp_kit/errors.py` | `ToolError`, `call_http` |
| `mcp_kit/paths.py` | `RootPolicy` — белый список каталогов |
| `mcp_kit/templates/` | заготовки `mcp_server.py`, `.env`, bat, тестов |
| `mcp_kit/cli.py` | `python -m mcp_kit.cli new <name> --out <dir> --port <port>` |
| `README.md` | полный гайд: сервер + плагин |

## Порядок (кратко; полный — в скилле)

1. Спросите: имя, порт, инструменты, кому отдавать (себе / клиентам).
2. `python -m mcp_kit.cli new <name> --out <dir> --port <port>`
   или скопируйте шаблоны из `mcp_kit/templates/`.
3. Замените `list_example` на инструменты. Существующий HTTP-сервер
   **не переписывайте** — оборачивайте: инструмент зовёт
   `http://127.0.0.1:порт/...` или импортирует функции.
   HTTP-ошибки — через `call_http`. Пути — через `RootPolicy`.
4. Тесты, `/health`, `tools/list`.
5. Плагин `dsh-plugin-<name>` по `references/dsh-plugin.md` из скилла.
6. Клиентский README (без MCP-деталей), npm pack, установка, рестарт DSH.

## Правила, которые нельзя нарушать

- Один `serverName` на хост. Дубль — инструменты откатываются.
- `require_key=True` — fail-closed. Ключ `secrets.token_urlsafe(32)`,
  в git не класть.
- Путь без `RootPolicy.resolve` — не принимать.
- README плагина — для клиента: что умеет, как поставить, «если не
  работает». Без патчей и npm publish.
- Персональная ссылка клиенту — через админку / `issue_license --plugin`
  проекта (пример: drawing5, `:8810`), не вшивая токен в публичный пакет.

## Что спросить, если не хватает

Не выдумывайте инструменты и пути. Спросите:

- какие данные и действия нужны модели;
- какие операции разрушающие;
- какие каталоги можно читать;
- клиенту — персональная ссылка или локальный профиль.
